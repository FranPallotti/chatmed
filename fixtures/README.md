# Fixtures

Synthetic test PDFs only (hard rules 8 and 9): every person, drug, company and value is invented.
They are generated by `scripts/make_fixtures.py` (`uv run python scripts/make_fixtures.py`); do
not edit the PDFs by hand.

## CIOMS I-style forms (D12, D13)

One synthetic case for tenant **acme**, subject **01001-004** of study ACM-101. The same subject
and event are in `db/seed/tenant_acme.sql` (`adsl` row `01001-004`, `adae` row with
`aeseq = 2`, start date 2026-06-12, drug withdrawn), so extracted facts can be joined to the
tenant database through `subject_id -> adsl.subjid`.

The layout follows the public CIOMS I form sections (I reaction, II suspect drug, III concomitant
drugs, IV manufacturer). Dates are written in ISO format (YYYY-MM-DD) so that the document text,
the extracted value and the seed match exactly. Patient initials and date of birth read
`PRIVACY`: they are not extracted (D12, data minimisation).

Like the real form (D13, M2 AC6):
- The subject id is printed with a site prefix, `Subject ID 101-01001-004`; the join in code
  matches its suffix `01001-004` against `adsl.subjid`.
- Checkboxes are drawn as graphics (a rectangle, plus an X when checked), never as text. The text
  layer has only the labels, and OCR of the scanned form shows noise around the boxes
  (`X]`, `[]`, `LJ`, ...). Tick marks are never read from text.
- The narrative (box 7+13) states "The patient was hospitalised on 2026-06-13.", so
  `hospitalisation` has a written source (`ok`). `dechallenge`, `rechallenge`, `report_type` and
  the other seriousness boxes have none: extraction reports them as `undeterminable`.

## Reproducibility check across platforms

`tests/test_parsing.py` regenerates the fixtures and compares them with the committed files:

- Digital fixtures: byte for byte (fpdf2 with a pinned creation date and built-in fonts).
- Image-only fixtures (`scanned_lab_report.pdf`, `mixed_report.pdf`, `cioms_initial_scanned.pdf`):
  the embedded raster and its compression can differ between Windows and Linux, so the bytes are
  not compared. Instead:
  - **Content:** `build_pdf` stores a sha256 of the fixture's source (page lines, scanned pages,
    layout, scan DPI) in the PDF Keywords (`source-sha256:...`); it must match the generator.
    Pixels cannot do this job: changing one digit of the form changes only ~0.001% of the pixels.
  - **Rendering:** same page count, no text layer on image-only pages, and each page rendered at
    72 DPI in grayscale has the same size and a mean pixel difference below 1%. This catches a
    wrong or broken raster and tolerates platform differences in font rasterization.
